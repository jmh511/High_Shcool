# 진법 변환 퀴즈 게임 (BASE CONVERTER QUIZ)

중학교 멘토링 수업용 **2진법 · 10진법 · 16진법 변환 실시간 퀴즈 게임**입니다.
멘토(관리자)가 방을 만들고, 학생들은 각자 스마트폰/노트북으로 접속해 카훗처럼 동시에 문제를 풉니다.
8비트 레트로 스타일 UI, 문제 자동 생성, 속도 보너스 점수, 실시간 리더보드를 지원합니다.

---

## 1. 실행 방법

### (1) 설치 — 처음 한 번만

```bash
npm install
```

### (2) 서버 실행

```bash
node server.js
```

실행하면 터미널에 접속 주소가 표시됩니다.

```
  관리자 화면 : http://localhost:3000/host
  참여자 화면 : http://localhost:3000/play
  (같은 와이파이) 참여자 접속 주소 : http://192.168.0.12:3000/play
```

### (3) 수업에서 쓰는 순서

1. 멘토 노트북에서 서버를 실행하고, 브라우저로 `http://localhost:3000/host` 접속 → **프로젝터/TV에 이 화면을 띄웁니다.**
2. 설정(문제 수, 제한시간, 난이도 비율)을 정하고 **[방 만들기]** 클릭 → 4자리 방 코드와 접속 주소, QR코드가 표시됩니다.
3. 학생들은 **같은 와이파이**에 연결한 뒤 화면에 뜬 주소(`http://192.168.x.x:3000/play`)로 접속 → 방 코드 + 닉네임 입력.
4. 대기실에 학생 이름이 모두 뜨면 **[게임 시작]** 클릭.
5. 문제 → 제한시간 → 정답 공개(풀이 + 순위)가 자동으로 반복됩니다.
   **참여자가 모두 답을 내면 제한시간이 남아도 바로 다음으로 넘어갑니다.**
   급할 때는 **[▶ 바로 정답 공개] / [▶ 다음 문제로]** 버튼으로 건너뛸 수 있습니다.
6. 마지막 문제가 끝나면 TOP 3 시상대 + 전체 순위 + 문제별 정답률이 표시됩니다.
   **[같은 방으로 다시 시작]** 을 누르면 같은 학생들과 새 문제로 한 판 더 할 수 있습니다.

> **주의**: 학생 기기가 접속되지 않으면 노트북 방화벽에서 3000번 포트가 막혀 있을 수 있습니다.
> Windows에서 "Node.js에 네트워크 접근을 허용하시겠습니까?" 팝업이 뜨면 **허용(개인 네트워크)** 을 선택하세요.

포트를 바꾸려면: `PORT=4000 node server.js`

## 2. 게임 규칙

### 문제
- 문제 은행 없이 **매 게임 서버에서 랜덤 생성**되므로 여러 번 해도 문제가 겹치지 않습니다.
- 변환 방향 6가지: `2→10`, `10→2`, `2→16`, `16→2`, `10→16`, `16→10`
- 난이도는 앞쪽 쉬움 → 중반 보통 → 후반 어려움 순으로 자동 상승합니다.

| 난이도 | 값 범위 | 특징 |
|---|---|---|
| ★ 쉬움 | 8~15 (4비트) | 2진수 4자리, 16진수 1자리 / 2↔10, 10↔16 위주 |
| ★★ 보통 | 16~255 (8비트) | 6가지 방향 전체, 16진수 2자리 |
| ★★★ 어려움 | 16~255 | 10진수를 거치지 않는 2↔16 직접 변환 비중 ↑ |

### 정답 판정
- **10진법으로 답하는 문제**: 정수 값으로 비교 → `011` 과 `11` 모두 정답
- **2진법·16진법으로 답하는 문제**: 앞자리 0이 없는 표준 형태만 정답 (`5` → `101` 정답, `0101` 오답)
  - 관리자 설정에서 **"앞자리 0이 붙은 답도 정답 처리"** 를 켜면 `0101` 도 정답이 됩니다.
- **16진법은 대소문자 무시** → `a9` = `A9`
- 참여자 화면에는 **문제 유형에 맞는 전용 키패드**만 나오므로 잘못된 문자는 입력 자체가 불가능합니다.
  (2진법 → `0` `1` / 10진법 → `0~9` / 16진법 → `0~9`, `A~F`)

### 문제 형식 — 직접 입력 / 4지선다

**직접 입력** 문제는 키패드로 답을 쓰고 [제출]을 누릅니다.

**4지선다** 문제는 보기 4개가 색깔별로 뜨고, **누르는 즉시 제출**됩니다(카훗과 같은 방식).
노트북 참여자는 `1`~`4` 숫자키로도 고를 수 있고, 관리자 화면(프로젝터)에도 같은 보기가 함께 표시됩니다.

오답 보기는 아무 숫자나 넣지 않고 **학생들이 실제로 하는 실수**로 만듭니다.

| 오답 유형 | 예 (10진법 8 → 2진법, 정답 `1000`) |
|---|---|
| 1 차이 (계산 실수) | `111`(7), `1001`(9) |
| 자릿수를 하나 밀림 | `10000`(16), `100`(4) |
| 두 자리를 바꿔 씀 | `0100` → `100` |
| 자리값을 거꾸로 읽음 | `0001` → `1` |

정답과 자릿수가 비슷한 오답을 우선 고르므로, 답이 눈에 띄게 티 나지 않습니다.

### 점수
- 정답: `500 + 500 × (남은시간 ÷ 제한시간)` → **빨리 맞힐수록 최대 1000점**
- 연속 정답 콤보(설정 ON): 2연속부터 `+100점`씩, 최대 `+500점`
- 오답 / 시간초과 / 미제출: 0점
- 문제가 끝날 때마다 누적 점수 기준 TOP 5 리더보드가 갱신됩니다.

## 3. 관리자 설정 항목

| 항목 | 기본값 | 설명 |
|---|---|---|
| 출제 범위 | 전체 | **전체**(2·10·16진법) / **2진법만**(2 ↔ 10진법) / **16진법 위주** |
| 문제 형식 | 섞어서 | **섞어서**(직접 입력 + 4지선다 절반씩) / **직접 입력만** / **4지선다만** |
| 총 문제 수 | 12 | 3~30 |
| 문제당 제한시간 | 20초 | 5~120초 |
| 어려움 제한시간 | 25초 | 어려움 난이도 문제에만 적용 |
| 난이도 비율 | 3 : 5 : 2 | 쉬움 : 보통 : 어려움 (비율이므로 합이 10이 아니어도 됨) |
| 앞자리 0 허용 | 꺼짐 | `0101` 같은 답도 정답 처리 |
| 콤보 보너스 | 켜짐 | 연속 정답 추가 점수 |
| 소리 | 켜짐 | 효과음 + 배경음악. 화면 **우측 상단 버튼**으로 언제든 끄고 켤 수 있습니다 |

### 출제 범위 — 2진법만 모드

아직 16진법을 배우지 않은 반이라면 **2진법만** 을 고르세요. 2진법 ↔ 10진법 변환만 출제됩니다.

| 난이도 | 2진법만 모드에서 나오는 문제 |
|---|---|
| ★ 쉬움 | 4비트 (8~15) — 2진수 4자리 |
| ★★ 보통 | 8비트 (16~255) |
| ★★★ 어려움 | 128~255 — 항상 2진수 8자리 |

## 4. 화면 구성

### 관리자 화면 (`/host`) — 교실 프로젝터/TV용

반 전체가 함께 보는 화면이라, 뒷자리에서도 읽히도록 글씨를 크게 잡고
넓은 화면을 활용하는 레이아웃으로 만들었습니다. 1920×1080 기준으로 스크롤 없이 한 화면에 들어갑니다.

| 화면 | 내용 |
|---|---|
| 대기실 | 방 코드(최대 140px) · 접속 주소 · QR · 참여자 카드 |
| 문제 | 원본 숫자(최대 110px) · 타이머(최대 64px) · **실시간 제출 현황** · 4지선다면 보기도 함께 |
| **정답 공개** | **왼쪽에 정답과 풀이, 오른쪽에 현재 순위를 나란히** — 학생들이 정답을 확인하는 동안 순위 변동도 같이 봅니다 |
| 최종 결과 | 우승자 · TOP 3 시상대 · 전체 순위 · 문제별 정답률 |

### 참여자 화면 (`/play`) — 개인 스마트폰/노트북용

| 화면 | 내용 |
|---|---|
| 문제 | 전용 키패드 또는 4지선다 보기 |
| **제출 완료** | 내가 낸 답 · **"○ / ○명 제출" 실시간 현황과 진행 바** · 남은 친구를 기다리는 애니메이션 |
| 결과 | 정답/오답 · 획득 점수 · 풀이 · 내 순위 |

## 5. 폴더 구조

```
binary-quiz-game/
├── server.js              # Express + Socket.IO 서버, 방 관리 / 진행 / 채점
├── quiz.js                # 문제 랜덤 생성, 정답 판정, 풀이 설명 생성
├── package.json
├── public/
│   ├── host.html          # 관리자(호스트) 화면
│   ├── play.html          # 참여자(플레이어) 화면
│   ├── css/retro.css      # 8비트 레트로 공통 스타일
│   ├── assets/sounds/     # (비워둬도 됨) 직접 구한 mp3를 넣는 곳
│   └── js/
│       ├── audio.js       # 8비트 효과음·배경음악 합성 엔진, 소리 on/off
│       ├── host.js
│       └── play.js
└── README.md
```

### 주요 Socket.IO 이벤트

| 방향 | 이벤트 | 내용 |
|---|---|---|
| 호스트 → 서버 | `host:create` / `host:start` / `host:next` / `host:restart` | 방 생성, 시작, 대기 건너뛰기, 재시작 |
| 참여자 → 서버 | `player:join` / `player:answer` | 입장(재접속 포함), 답 제출 |
| 서버 → 전체 | `room:created`, `room:players`, `game:question`, `game:submitCount`, `game:reveal`(정답+순위), `game:final`, `game:reset` | 방/문제/정답/순위 브로드캐스트 |
| 서버 → 개인 | `player:joined`, `player:submitted`, `player:result`, `player:final` | 본인 결과·점수·순위 |

방 상태는 **서버 메모리에만** 저장되며 DB를 쓰지 않습니다. 서버를 끄면 모든 데이터가 사라지므로 개인정보가 남지 않습니다.

## 6. 알아두면 좋은 점

- **재접속 지원**: 학생이 실수로 창을 닫아도 같은 브라우저에서 다시 접속하면 점수를 유지한 채 돌아옵니다. (같은 탭 세션 기준)
- **중간 입장 불가**: 게임이 시작된 뒤에는 새 참여자가 입장할 수 없습니다. 늦은 학생은 다음 판에 참여시키거나, 대기실에서 조금 기다렸다 시작하세요.
- **인원**: 기본 상한 40명 (`server.js`의 `DEFAULT_SETTINGS.maxPlayers`에서 변경 가능).
- **오프라인 교실**: 인터넷 없이 로컬 와이파이만으로 동작합니다. 다만 인터넷이 없으면 픽셀 폰트(Google Fonts)와 QR코드 이미지는 표시되지 않고 기본 글꼴로 대체됩니다. 게임 진행에는 문제가 없습니다.
- **소리**: 별도 음원 파일 없이 Web Audio API로 8비트 효과음과 배경음악을 직접 합성합니다.

  | 배경음악 | 언제 |
  |---|---|
  | 대기실 곡 | 방을 만든 뒤 참여자를 기다리는 동안 |
  | 게임 곡 | 문제를 푸는 동안 계속 (문제 집중을 방해하지 않게 작게) |
  | 승리 곡 | 최종 결과 화면 — 팡파레가 끝난 뒤 반복 재생 |

  - **끄고 켜기**: 모든 화면 우측 상단에 **[🔊 효과음]** 과 **[🎵 배경음악]** 버튼이 **따로** 있습니다. 효과음만 끄고 배경음악만 틀거나 그 반대도 됩니다. 설정은 브라우저에 저장되어 새로고침해도 유지되고, 관리자 화면과 학생 기기가 서로 영향을 주지 않습니다.
  - **직접 구한 mp3를 쓰려면**: `public/assets/sounds/` 에 `lobby.mp3` · `game.mp3` · `victory.mp3` 를 넣으면 합성음 대신 그 파일이 재생됩니다. 자세한 내용은 [해당 폴더의 안내](public/assets/sounds/README.md)를 보세요.

## 7. 인터넷에 배포하기 (선택)

교실 와이파이로 충분하다면 배포할 필요가 없습니다. **학생들이 각자 데이터로 접속해야 하거나,
학교 와이파이가 기기끼리 통신을 막아둔 경우**에만 배포하세요.

### 이 앱에 맞는 배포처

WebSocket을 계속 물고 있어야 하고 방 정보를 서버 메모리에 두므로,
**서버가 항상 떠 있고 인스턴스가 1개인** 곳이어야 합니다.
Vercel·Netlify 같은 서버리스 호스팅은 이 구조에 맞지 않습니다.

| 배포처 | 비용 | 참고 |
|---|---|---|
| **Render** (추천) | 무료 | 설정 파일(`render.yaml`)이 이미 있어 클릭 몇 번이면 끝. 15분간 아무도 안 들어오면 잠듦 |
| Railway | 월 $5 정도 | 잠들지 않아 수업 직전 준비가 편함 |
| Fly.io | 무료 한도 있음 | CLI 설치 등 준비가 조금 더 복잡 |

### Render 배포 순서

1. https://render.com 가입 (GitHub 계정으로 로그인하면 편합니다)
2. 대시보드에서 **New +** → **Blueprint**
3. `jmh511/High_Shcool` 저장소 선택 → 저장소 루트의 `render.yaml` 을 자동으로 읽습니다
4. **Apply** → 3~5분 뒤 `https://binary-quiz-game.onrender.com` 같은 주소가 생깁니다
5. 수업에서는 관리자 `.../host`, 학생 `.../play` 로 접속

이후 `git push` 할 때마다 자동으로 다시 배포됩니다.

### 배포했을 때 꼭 알아둘 점

- **무료 요금제는 15분간 접속이 없으면 잠듭니다.** 잠든 상태에서 처음 열면 깨어나는 데 **50초쯤** 걸리니,
  **수업 시작 2~3분 전에 관리자 화면을 미리 열어두세요.**
- **잠들거나 재배포되면 진행 중이던 방과 점수가 사라집니다.** 방 정보를 서버 메모리에만 두기 때문입니다.
  수업 도중에는 `git push` 를 하지 마세요.
- **인스턴스를 2개 이상으로 늘리면 안 됩니다.** 학생이 다른 서버에 붙어 방 코드를 못 찾게 됩니다.
  (`render.yaml` 에 `numInstances: 1` 로 고정해 두었습니다)
- 배포하면 주소가 `https://` 로 바뀌고 방 코드 입장 방식은 그대로입니다. QR코드도 그대로 동작합니다.
